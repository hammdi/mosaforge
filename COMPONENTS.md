# Components and their role in MosaForge

Verdicts: **Keep** (use as-is) · **Adapt** (wrap behind a MosaForge interface) · **Borrow** (reuse
ideas or selected files, with attribution) · **Defer** (revisit at a roadmap gate) · **Reject**.
All sources are pulled into `upstream/` for inspection (see [upstream/MANIFEST.md](upstream/MANIFEST.md)).
Nothing in `upstream/` is imported or executed by MosaForge.

## What MosaForge owns itself

1. **Interfaces**: `ModelProvider`, `Tool`, agent contract, `Memory`, `Router`, `TaskRecord` ([mosaforge/core.py](mosaforge/core.py)).
2. **Routing policy and escalation**, including privacy rules and experience-based adjustment ([router.py](mosaforge/router.py), [orchestrator.py](mosaforge/orchestrator.py)).
3. **Verification policy** ([verify.py](mosaforge/verify.py)): deterministic checks first; never trust an agent's own "tests pass".
4. **One memory + experience store** ([memory.py](mosaforge/memory.py)).
5. **LAN worker protocol and its security model** ([worker.py](mosaforge/worker.py)).
6. **Evaluation suite and benchmark harness** ([bench.py](mosaforge/bench.py)).
7. **The MCP surface** that lets any supervisor (Claude Code today) delegate ([mcp_server.py](mosaforge/mcp_server.py)).

Everything else is someone else's job, plugged in behind those interfaces.
